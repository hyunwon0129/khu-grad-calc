# 로그인 기능 보안 검토 (v0.17.0)

구조: 정적 사이트(Netlify) + Supabase(인증·DB). 직접 운영하는 서버 없음. 사정표 PDF는 브라우저 안에서만 분석하고 서버로 보내지 않는다.

## 지키는 것

| 항목 | 방법 | 확인 |
|---|---|---|
| 사정표 파일·이름·학번·성적 | 서버로 보내지 않음. 저장 필드를 `sanitize`로 제한, 평점 값은 버림 | 가짜 서버 테스트: 업로드 본문 키가 허용 8개뿐, 평점 detail 없음 |
| 다른 사람 데이터 | RLS: 본인 행만 조회·생성·수정·삭제. 비로그인(anon) 권한 없음 | 로컬 PostgreSQL에서 A 기록을 B가 조회 0행·수정 0행·삭제 0행, anon은 권한 오류 |
| 브라우저 검사 우회 | 서버 트리거가 허용 키만 남기고, `user_id`를 요청자로 고정, 형식·개수 검사, 크기 200KB 제한 | `user_id`를 남의 것으로 넣어도 본인으로 저장, `name`·`gpa`·`studentId` 키 제거, 배열·잘못된 형식 거부 |
| 이중 방어 | 조회·삭제에 `user_id = 본인` 조건도 붙임 (RLS를 잘못 설정해도 남의 행을 건드리지 않게) | 요청 주소 `user_id=eq.<본인>` 확인 |
| 같은 기기의 다른 사람 기록 | 이 기기 기록의 주인 계정을 기억. 로그인 전 기록·다른 계정 기록은 **묻기 전에 올리지 않음** | 가짜 세션 테스트: 묻기 전 업로드 0건, '비우고 시작' 시 기기 기록 삭제 |
| 공용 PC | '이 기기에 저장 안 함' 모드면 로그인 정보도 sessionStorage(탭 닫으면 삭제). 로그아웃 시 기기 기록 지우기 선택 가능 | |
| 외부 전송 | CSP `connect-src 'self'` + 설정한 Supabase 주소 1개만. 그 밖의 주소로는 브라우저가 전송 차단 | 테스트: example.com 전송 차단, 사정표 분석 중 외부 요청 0건 |
| 스크립트 주입 | CSP `script-src`가 'unsafe-inline' 대신 앱 코드의 sha256 해시만 허용. React 기본 이스케이프 | 배포 파일에서 앱 정상 동작·CSP 위반 0건 |
| 클릭재킹 | `X-Frame-Options: DENY`, `frame-ancestors 'none'` (Netlify 헤더) | |
| 로그인 방식 | 비밀번호 없음 (이메일 링크·OAuth, PKCE). 비밀번호 유출·대입 공격 대상 없음 | |
| 비밀 키 | 브라우저에는 공개용 anon 키만. service_role 키는 회원 탈퇴 함수(서버) 안에서만 | 저장소·빌드 결과에 service_role 없음 |
| 회원 탈퇴 함수 | 요청자 토큰으로 본인 확인 후 본인만 삭제. CORS는 `ALLOWED_ORIGINS`의 주소만. 내부 오류 문구는 밖으로 안 냄 | |
| 오류 메시지 | 서버 오류 원문(토큰 등이 섞일 수 있음)을 화면에 그대로 띄우지 않고 한국어 안내로 바꿈 | 테스트: 원문에 넣은 `SECRET`이 화면에 안 나옴 |
| 동의·삭제 | 로그인 전 저장 항목 동의, 서버 데이터 삭제·회원 탈퇴 버튼 | |

## 남은 위험과 대응

- **세션 토큰이 localStorage에 있음** (Supabase 기본). XSS가 있으면 탈취될 수 있어 CSP 해시·외부 스크립트 0개로 막는다. 토큰을 가져가도 할 수 있는 일은 그 사람의 과목 기록 조회·수정뿐.
- **로그인 메일 남용**: Supabase 기본 발송 제한에 의존. 공개 시연 전에 Authentication → Bot and Abuse Protection에서 CAPTCHA를 켜면 더 안전하다 (켜면 CSP에 CAPTCHA 주소 추가가 필요).
- **로그인 링크 피싱**: 메일 링크는 Supabase가 허용한 Redirect URL로만 돌아온다. Redirect URLs에 와일드카드를 넣지 말 것.
- **공용 PC에서 로그아웃을 잊음**: 공용 PC 모드를 쓰도록 안내.
- **사정표 분석 결과(영역별 학점·학과·입학연도)는 서버에 저장됨**: 성적이 아니라 이수 학점이지만 학업 정보이므로 동의문과 개인정보처리방침에 명시했다.

## 테스트 방법

- 단위·화면 테스트: `npm test`, 배포 파일 Playwright 테스트
- 서버 규칙: `supabase/schema.sql`을 로컬 PostgreSQL 16에 auth 흉내(auth.uid)와 함께 적용해 RLS·트리거 확인
- 로그인 흐름: 가짜 Supabase 응답(Playwright route)으로 동의·오류 안내·업로드 전 확인·업로드 본문 확인
